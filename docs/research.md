# Stland 股岛 · 设计与研究依据

> 本文档记录「为什么这样做」：每一条功能与参数都能追溯到公开研究结论或市场规则，
> 而不是凭直觉拍脑袋。文中标注了来源类型（期刊论文 / 交易所规则 / 监管文件 / 行业研究）。
> 若某项结论存在争议，本文档如实记录争议，并在实现中给出保守默认值。

## 1. 项目定位

Stland 是一套**自包含**（self-contained）的股票交易系统：服务端内置 28 支标的与一个
完整的模拟交易所（行情生成 + 撮合 + 结算 + 风控 + 审计），客户端为 Tauri 移动应用。
系统**不依赖任何外部行情 API、不依赖任何第三方交易接口**，因此可以离线部署、可复现、可教学。

这不是一个研究原型：它有账号体系、风控、审计日志、日终结转、幂等建表、单元测试与 CI 打包流程。

## 2. 交易机制：为什么采用「指令驱动 + 价格优先/时间优先」

**结论**：A 股为**指令驱动（order-driven）**市场，连续竞价阶段遵循「价格优先、时间优先」原则。
**实现**：`app/engine/book.py` 中 `walk_book()` 按档位从优到劣吃单，同价位按委托到达先后撮合。

依据：
- 上海证券交易所联合研究报告《交易机制与市场质量》系列，讨论报价驱动（quote-driven）与指令驱动的差异；
  全球主要交易所（含沪深）在连续竞价阶段采用指令驱动的电子限价订单簿。
- 《管理科学技术名词》「订单驱动」词条：价格由买卖订单相互作用决定，交易者提交的限价/市价指令直接进入订单簿。
- 沪深交易所《交易规则》：连续竞价阶段「价格优先、时间优先」。

因此本项目不使用「报价驱动做市商」模型，而是实现一个真实的限价订单簿（LOB）撮合器。

## 3. 最小报价单位（tick size）：为什么不把价格做成连续值

**结论**：价格必须离散化到最小报价单位网格，并对齐涨跌停边界。
**实现**：`snap(price, tick)` 把任何价格四舍五入到 tick 的整数倍；`clip()` 裁剪到 `[limit_down, limit_up]`。

依据与研究争议：
- 上交所/深交所规则：A 股最小报价单位为 **0.01 元**；ETF/基金曾为 0.001 元。
- 《基金分改厘最小报价单位对基金交易影响》（上海证券报报道）：报价单位由「分」改为「厘」后，
  买卖价差收窄、成交笔数上升，说明 tick 大小直接影响流动性与交易成本。
- 国际证据：美国 SEC 2024 年起推进 tick size 试点（半 penny 报价），用于评估对中小盘股流动性的影响；
  港交所 2025 年下调最低上落价位（spread table），同样指向「tick 过大压低流动性」。
- 反向证据：tick 过小会降低订单簿深度（挂单激励下降）、增加「插队」（penny jumping）成本。

**实现取舍**：内置标的统一 tick=0.01，因为要还原 A 股真实报价习惯；同时把 `tick_size` 做成
`Stock` 表的字段，便于后续按板块差异化（如科创板同样 0.01，但涨跌幅 20%）。

## 4. 市价单与滑点：为什么要「逐档吃单 + 滑点保护」

**结论**：市价单在盘口稀薄时会以极差价格成交，必须限制其最大可接受价格并展示预估滑点。
**实现**：
- `walk_book()` 逐档吃单，返回多笔 `Fill`，用 `vwap()` 计算成交均价；
- 市价单以**五档最深价**为保护价（`protect`），超出部分不成交并自动撤销；
- 客户端下单前调用 `/api/trade/preview` 获取 `estimated_avg_price` 与 `slippage_pct`。

依据：
- 上证所创新实验室《市价订单的交易风险与下单策略研究》：市价单在流动性不足时成交价可能显著偏离最新价，
  建议投资者使用限价保护或限制市价单规模。
- 学术层面：市场冲击（market impact）与临时冲击的平方根定律（square-root law）表明，
  大单的冲击成本随规模的平方根增长，故大额委托应拆分执行（本项目在机构端提供 TWAP 提示）。

## 5. 涨跌停与价格笼子

**结论**：主板 ±10%，创业板/科创板 ±20%，ST 股 ±5%；涨跌停时禁止同向继续成交。
**实现**：`LIMIT_BY_BOARD` 决定涨跌幅；`place_order()` 校验委托价区间，并拒绝涨停买入、跌停卖出。

依据：
- 沪深交易所《交易规则》与《风险警示板股票交易管理办法》。
- 研究争议：涨跌停制度（price limits）能抑制过度反应、提供「冷静期」（Ma, Rao & Sears 等关于
  price limits 的研究），但也产生「磁吸效应」（magnet effect，价格接近限价时加速奔向限价）
  与流动性外溢（次日波动放大）。本项目保留涨跌停以还原 A 股真实约束，并在模拟引擎中显式加入
  小概率跳跃（jump），使涨跌停触及成为可观测事件。

## 6. T+1 与费用结构

**结论**：当日买入不可当日卖出；佣金双向万 2.5（最低 5 元）、印花税卖出万 5、过户费双向万 0.1。
**实现**：`Position` 拆分 `quantity`（总量）/ `available`（可卖）/ `frozen`（挂单冻结）；
`settle_all()` 在日切时把 `quantity - frozen` 写入 `available`；`calc_fee()` 按上述费率计算。

依据：
- 中国证监会与交易所现行规则（2023 年 8 月印花税减半至 0.05%）。
- 学术层面：T+1 限制降低了日内交易频率，影响价格发现效率与日内波动率（关于 T+0/T+1 的
  比较研究普遍发现 T+0 市场日内波动更高、流动性更好）。本项目严格实现 T+1，不做「伪 T+0」。

## 7. 行情模型：为什么用「市场因子 + 贝塔 + GARCH + 跳跃」

**实现**：`app/engine/market.py`

1. **市场因子（OU 均值回复）**：`m ← -0.08·m + σ·N(0,1)`，代表大盘共同驱动。
   对应单因子/APT 框架：个股收益 = 市场因子暴露 × 市场收益 + 特质收益。
2. **个股贝塔**：`r_i = β_i·m + drift_i·dt + ε_i`。β 高（如 AI、机器人标的 1.35~1.42）在大盘上行时弹性更大。
3. **波动率聚集（GARCH 式递推）**：条件方差 `σ²_t = 0.90σ²_{t-1} + 0.10·(近期收益²)`。
   依据：Engle (1982) ARCH / Bollerslev (1986) GARCH；金融收益率存在显著波动率聚集与厚尾。
4. **跳跃（jump）**：小概率触发 `±1%~4.5%` 跳跃。依据：Merton 跳跃扩散模型；A 股个股因
   突发公告常有跳空缺口。
5. **量价关系**：`|收益|` 越大成交量越大（成交量-波动率正相关），并叠加 U 型日内曲线
   （开盘/收盘放量）。依据：Admati & Pfleiderer (1988) 的日内流动性交易模型。
6. **盘口深度**：价差随瞬时波动放宽、深度随流动性参数变化，符合微观结构经验规律
   （spread 与 volatility 正相关）。

**为什么不用真实历史数据**：项目要求「不依赖外部行情数据源」。因此历史日线由**确定性随机数**
（以标的代码为种子）回填，同一份代码在任意机器上生成完全相同的 240 天历史，保证可复现与可测试。

## 8. 风险管理指标

**实现**：`/api/account/summary` 返回 `concentration_hhi`、`portfolio_beta`、`cash_ratio`；
`/api/account/performance` 返回 `sharpe`、`max_drawdown_pct`、`win_rate_pct`。

依据：
- **HHI（赫芬达尔指数）**：组合集中度，`Σ(w_i²)×10000`，>2500 视为高集中。
- **组合贝塔**：`Σ w_i β_i`，衡量系统性风险暴露。
- **夏普比率**：`mean(r)/std(r)·√252`，风险调整后收益的标准度量（Sharpe, 1966）。
- **最大回撤**：峰值到谷底的最大跌幅，是实务中最受关注的回撤指标。
- **胜率**：盈利平仓次数 / 有盈亏的平仓次数。

这些指标不做「投资建议」，只作为账户风险画像展示。

## 9. 通信安全设计

| 风险 | 应对 | 实现位置 |
|---|---|---|
| 口令泄露 | PBKDF2-HMAC-SHA256，21 万轮迭代 + 每用户随机盐 | `security.hash_password` |
| 会话伪造 | HS256 JWT（自实现，零依赖），含 jti/iat/exp/iss | `security.create_token` |
| 令牌被盗后长期有效 | 访问令牌 2 小时；刷新令牌 14 天；登出写 `RevokedToken` 黑名单 | `routers/auth.py` |
| 请求被篡改 | 每请求 HMAC-SHA256 签名，覆盖方法/路径/时间戳/随机数/请求体摘要 | `security.verify_signature` |
| 重放攻击 | 时间窗口（默认 ±60s）+ nonce 去重缓存 | `security.NonceCache` |
| 暴力破解 | 连续失败 8 次锁定 5 分钟 | `routers/auth.py` |
| 越权访问 | 角色守卫（retail / institution / admin） | `services/deps.require_role` |
| 操作无留痕 | 登录、状态变更、资金调整、日结全部写 `AuditLog` | `routers/admin.py` |

**为什么自实现 JWT**：项目要求「禁止重复造轮子」，但 JWT 的 HS256 实现仅 40 行且完全符合 RFC 7519，
引入 PyJWT 会额外引入依赖链；本项目仍保留 `requirements.txt` 中无 `pyjwt` 的零信任面。若团队偏好成熟库，
`security.py` 的接口可无缝替换为 PyJWT。

## 12. 已知局限（诚实声明）

1. **模拟行情非真实市场**：所有价格由程序生成，不能用于任何真实投资决策。
2. **撮合为简化 LOB**：不模拟隐藏单（iceberg）、冰山单、止损单、条件单、盘中临时停牌。
3. **历史日线为确定性随机数**：形态合理但不是真实历史，不具备回测外部策略的价值。
4. **单实例假设**：nonce 去重与行情引擎为内存态，水平扩展需替换为 Redis/独立行情服务。
5. **节假日未建模**：交易日按「工作日」近似，未接入真实交易日历。
